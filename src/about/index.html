About This Site

Note: This page explains only the technical, nerdy details of this site. It is not an explanation of how this site is fundamentally meant to be used.

How was this site made?

This site was built by Claude Code. 😔

All sheet music is rendered on the webpage using VexFlow, an open-source music notation rendering library.

The icons on this site come from four places.

  • Most generic icons come from Phosphor Icons, a free icon family under the MIT licence.
  • Icons that are plain musical notation come from Bravura, the reference font for SMuFL (Standard Music Font Layout).
  • The favicon was drawn by myself in Adobe Illustrator.
  • The rest of the icons were drawn by Claude Code.

You can find the GitHub repo containing all of the code for this site here.

How does the difficulty system work?

There is no well-defined meaning to a difficulty of 2.5, say; the difficulty scale is mostly vibe-based. As a rough guideline,

  • A difficulty of 0.5 is the easiest possible transcription that is not completely trivial.
  • A difficulty of 5.0 is the hardest possible transcription that is reasonably human-feasible.
  • Now interpret all of the difficulties in between via linear interpolation.

Due to the subjectivity of the difficulty system, each tune's difficulty is set to a weighted average of all suggested difficulties for that tune.

Specifically, the author's suggested difficulty counts as four votes, and every other suggestion counts as one. This weighted average is then rounded to the nearest multiple of 0.5.

How is median completion time calculated?

A completion does not contribute toward the median completion time statistics if it was the author's completion, if assist mode was used, or if the user has opted out of contributing to public statistics. A median time only appears after three qualifying completions.

Where is my progress saved?

If you're signed out, then your progress on a tune is stored in your own browser's local storage. Notably, nothing you do while signed out is ever recorded in a database. You can tamper with your stored progress using DevTools if you'd like.

If you're signed in, then your progress on any given tune is stored in its own individual row in a database. (Deleting your account will delete all database rows associated with your account.)

How does browser progress merge with account progress?

Whenever you sign in on a browser that already has some progress stored within its local storage, the site will give you the option to merge the progress stored in local storage with the progress stored in the database.

If you do choose to merge, here is how the site decides whether to use the browser's progress or the database's progress for each tune.

  • A solved tune always wins over an unsolved tune.
  • An unfinished tune always wins over a not-started tune.
  • Between two solves, the one with fewer checks wins, then the shorter clock, and then the account by default.
  • Between two unfinished attempts, the one with more correct pitches wins, then the one with more pitches written, and then the account by default.
  • If assist mode usage was recorded in either the browser's progress or the database's progress, the merge will also record assist mode usage.
  • The merge takes written pitches, number of checks, clock, and solve from the winner's data. The only other thing carried over from the loser is its verdicts; that is, all of the feedback received from the answer-checker, both in the browser and the database, is combined in the merge.

Merging only affects user progress on public tunes. It always preserves your account's tunes, your upvotes, and your difficulty suggestions.
